# Peetri Pizza: запуск обновления из GitHub

Этот workflow **не выкладывает ничего автоматически**. Он запускается вручную в `Actions` → `Peetri Pizza — manual deploy` → `Run workflow` из ветки `main`. По умолчанию выбран `check`: подключение по SSH, проверка папки и текущей версии без изменения файлов. `deploy` применяет существующий `patches/update-latest-ssh.txt`. Его механизм сверяет контрольные суммы, делает резервные копии затрагиваемых файлов, выполняет PHP-проверки и откатывает записанные файлы при неудаче проверки.

## Первоначальная настройка (один раз)

Нужна отдельная SSH-пара ключей **без пароля**, специально для GitHub Actions, с доступом только к аккаунту размещения Peetri Pizza. Публичную часть добавьте на сервер в `~/.ssh/authorized_keys` указанного SSH-пользователя; приватную храните **только** в GitHub Secret, не в чате и не в репозитории. Сначала проверьте вход этим ключом с доверенного компьютера.

В репозитории `Settings` → `Secrets and variables` → `Actions` (или в `Settings` → `Environments` → `peetri-production` → `Environment secrets`) настройте:

| Имя | Содержимое |
|---|---|
| `PP_SSH_HOST` | **Точный** SSH-хост сервера Peetri Pizza (не домен сайта, если сервер отдельный). |
| `PP_SSH_USER` | SSH-пользователь сервера. |
| `PP_SSH_PORT` | Необязательно: порт SSH (по умолчанию `22`). |
| `PP_SSH_PRIVATE_KEY` | Полный приватный SSH-ключ, включая строки BEGIN/END. |
| `PP_SSH_KNOWN_HOSTS` | Строка `known_hosts` для этого сервера и порта. Отпечаток ключа сверяйте по независимому доверенному источнику; не принимайте непроверенный результат `ssh-keyscan` за доказательство подлинности сервера. |
| `PP_APP_PATH` | **Точный абсолютный путь** к рабочей папке приложения, заканчивающийся `/peetripizza`, где лежат `dashboard.php` и `auth/bootstrap.php`. |

Если требуется дополнительное подтверждение запуска, добавьте в `peetri-production` правило `Required reviewers` (при поддержке GitHub). Не вводите SSH-пароль или ключ в Issues, PR, Actions inputs или этот чат.

## Первый запуск

1. Запустите `check`. В логе должна появиться строка `Verified Peetri Pizza directory` с **правильным** путём и `Current app version`.
2. Сверьте показанную версию с ожидаемой и убедитесь, что это нужный сервер. Ошибку `check` исправьте в секретах или настройке SSH — не обходите проверку.
3. Только после успешного `check` выбирайте `deploy`. Перед выполнением патча вновь выполняется проверка того же пути. Workflow запускается только из `main` и не реагирует на обычные `push`.
4. После обновления проверьте на планшете LIVE, список заказов, таймеры, печать и выдачу. Эти проверки рабочего процесса требуют ручного контроля: успешная команда не доказывает работоспособность всех внешних сервисов.

**Откат:** если внутренние проверки патча не прошли, патч восстанавливает изменённые файлы автоматически. Для ручного отката используется путь, выведенный патчем в логе (`Бэкап изменяемых файлов`); не выполняйте слепое копирование поверх актуального состояния и не трогайте `private_data`. Кнопку ручного отката следует добавлять отдельно после проверки процесса восстановления на тестовой копии.
